A Go or C call argument that names a constant declared in another file now carries its value, so a key size written as const bits = 3072 in one Go file and used in a sibling file of the same package, or #define BITS 4096 in a header pulled in with #include "bits.h", is reported as resolved_value. Go reads package-level const declarations from the other .go files in the same directory and package. A _test.go declaration is visible only to another _test.go file. The value is dropped when the name is declared more than once in the package (for example a const per build tag, or a var, func or type of the same name), or when the declaring file carries a //go:build or // +build line or a _GOOS or _GOARCH file-name suffix, because the build decides which one applies. C follows quoted includes only, resolved relative to the including file and through nested headers up to eight levels deep (an include cycle is followed once). Angle-bracket system headers, an include that names no file or gives an absolute path, an include under #if or #ifdef, and a chain deeper than eight levels give no value. Inside the header the same rule as for a source file applies: only an unconditional object-like literal #define counts, and a whole-file include guard is allowed. The value is dropped when two different headers touch the name, when the including file defines or undefines it before the call, or when it is defined before the include. A quoted include that names no file on disk (a generated header, for example), a computed include such as #include HEADER, an #include_next and an #import after a define may redefine it, and so does any such include inside a header the including file pulls in after the define, so a define followed by one before the call gives no value, in the including file and inside a header alike. A Go package with a sibling file too large to read gives no value.
