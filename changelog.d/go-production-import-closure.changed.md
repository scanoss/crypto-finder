- Go `--scan-dependencies` now inventories the production import closure, the modules that provide a package imported directly or transitively by a non-test package of the project, instead of every module `go list -m all` reports. Modules required only by `_test.go` files or by build-tagged tool files such as `tools.go`, and requirements nothing imports, are no longer resolved or scanned, so fewer dependencies are scanned and reported: crypto-finder's own module goes from 111 to 44. Build constraints are evaluated for the scanning host's `GOOS`, `GOARCH` and build tags, and `--include-tests` does not widen the inventory. A package the go tool cannot load, such as one whose module is missing from the module cache while offline, is now skipped with a warning instead of failing Go dependency resolution with `dependency_resolution_failed`.
