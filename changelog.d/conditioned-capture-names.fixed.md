- A finding specialized by a parameter condition now fills its metadata placeholders (`$family`, `$mode`, `$padding`, ...) by name. The names come from the rule's own named groups applied to the resolved value, so `AES/GCM/NoPadding` reads family AES and mode GCM, and `RC4` keeps its name. Before, the names were taken from the position of the condition's groups, which shifted fields (family `CBC`, mode `PKCS5Padding`) or left them blank when the condition captured fewer groups than the rule names. The blank generic anchor of a dynamic selector call is no longer reported beside the per-value assets that replace it. It stays when no value resolved, and when any route into the call is not accounted for by a per-value asset: a caller whose value is dynamic, a value no rule variant matches, or an enumeration cut short. The rule's own regexes bind the way semgrep's `metavariable-regex` does, from the start of the value: a regex that does not end in `$` binds on a prefix, and one that does is matched in full.
