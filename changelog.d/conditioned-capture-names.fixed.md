- A finding specialized by a parameter condition now fills its metadata placeholders (`$family`, `$mode`, `$padding`, ...) by name. The names come from the rule's own named groups applied to the resolved value, so `AES/GCM/NoPadding` reads family AES and mode GCM, and `RC4` keeps its name. Before, the names were taken from the position of the condition's groups, which shifted fields (family `CBC`, mode `PKCS5Padding`) or left them blank when the condition captured fewer groups than the rule names. The blank generic anchor of a dynamic selector call is no longer reported beside the per-value assets that replace it. It stays when no value resolved.
