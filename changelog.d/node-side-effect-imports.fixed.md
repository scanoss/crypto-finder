- Importing a project module now reaches the code it runs when it loads. A JavaScript or TypeScript module's top level runs when another module imports it, but nothing linked the importer to it, so crypto at the top level of the imported module, or in a callback it registers there (`api.handle('channel', async () => ...)`), read as a root nothing calls even though an entry point imports it. The importer's top level now has an `exact` edge to the imported module's top level for a relative `import './x'`, `import a from './x'`, `export ... from './x'`, `export * from './x'` and a top-level `require('./x')`, resolved as other relative imports are (explicit extensions, `index` files). A module nothing imports stays unreachable. No edge is added for a package import, a dynamic `import()`, or a `require` inside a function (which runs only when that function does). TypeScript erases some imports, and those add no edge either: `import type` / `export type ... from`, a clause whose specifiers all carry the inline `type` keyword, and, in a `.ts`/`.tsx`/`.mts`/`.cts` file, an import whose names are never used as a value. A name used only as `typeof X` in a type counts as a value use and keeps the edge, as does any import in a JavaScript file; a bare `import './x'` always counts.
