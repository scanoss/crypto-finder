- Key length now resolves for key generation whose size is named by a parameter rather than passed as a number. Go `dsa.GenerateParameters(&p, rand.Reader, dsa.L2048N256)` reports 2048 (L1024N160 is 1024, L2048N224 and L2048N256 are 2048, L3072N256 is 3072). Go `ecdsa.GenerateKey(elliptic.P256(), rand.Reader)` and Python `ec.generate_private_key(ec.SECP384R1())` report the curve's field size (P-224 to P-521, the SECP, SECT and Brainpool classes in `cryptography`). Bouncy Castle `new RSAKeyGenerationParameters(e, random, 3072, certainty)`, `DSAParameterGenerationParameters`, and `DSAParametersGenerator`, `DHParametersGenerator` and `ElGamalParametersGenerator` `.init(size, certainty, random)` report their strength in bits, and a generator's `init(params)` reads it from the parameter object. A curve name or parameter set the tables do not list, and a curve held in a Python local variable, still report no key length. A new contract derivation, `argument_parameter_set_bits`, reads the DSA constant. (#716)
- Java `KeyPairGenerator.initialize(new ECGenParameterSpec("secp256r1"))` no longer exports the `initialize(int)` overload's signature. The contract's `int` parameter type was stamped onto the `AlgorithmParameterSpec` overload, so the call read the curve name as a size and reported `provenance: "unknown"` while the spec constructor reported 256. A call whose argument is an object no longer takes a primitive contract's parameter types, and its size now comes from the spec and agrees with the constructor. (#716)
