- A finding on a line where an anonymous function also starts is now attributed to the function that encloses the call, not to the callback. `crypto.generateKeyPair('rsa', { modulusLength: 2048 }, (err, pub, priv) => {` used to lose its `crypto_call` and `supporting_call_ids` (so no `resolved_key_length`), or report the user's call inside the callback as `matched_operation`. Function containment now uses the finding's start column as well as its line: a function that starts later on the finding's line does not contain it. Function spans carry start and end columns for every parser (a Java method or constructor starts at its first modifier on the signature line, so a rule match beginning at `public` is still inside it); a finding or function without a column is still judged by line. Findings on such lines get a different `occurrence_key`, because the key names the containing function. (#722)
