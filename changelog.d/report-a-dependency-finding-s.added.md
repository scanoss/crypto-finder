- `finding_graphs[].dependency` on the live and stitched callgraph exports (`graphfrag.ExportFindingDependency`): a dependency finding names the dependency it sits in (`module`, `version`, `purl`), whether the application depends on it `direct`ly or `transitive`ly (`relationship`), and its shortest route from the application in the resolved dependency graph (`path`, a direct dependency first and the finding's dependency last, each with `module`, `version` and `purl`). A route through dependencies parsed with source is preferred over a shorter one that is not. First-party findings carry no block, and the top-level `purl` still names the rule's library on first-party findings only. Optional, and declared in the `6.14`, `6.15` and `6.16` schemas without a version change, because `finding_graphs[]` items already admitted additional properties.
- A dependency that joined the call graph without source code (a Java dependency with no source JAR, indexed for types only) is no longer silent. On a finding's `dependency.path` it carries `without_source: true`, and a dependency finding that no chain reaches, and whose every route from the application crosses such a dependency, reads `unknown` with `unresolved_reason: "dependency_without_source"` and `analysis.call_chains: "partial"` instead of `unreachable`, since its chain may run through calls the graph does not hold.
