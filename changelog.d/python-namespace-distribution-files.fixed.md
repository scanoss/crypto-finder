- Python `--scan-dependencies` now attributes each file in a namespace directory to the one distribution that installed it. Distributions that install into one namespace directory, such as `protobuf`, `googleapis-common-protos`, `google-auth` and `google-api-core` with `google/`, all resolved to that directory, so each of them scanned the whole namespace and every finding in it was reported once per distribution, under the wrong distribution for all but one of the copies. Each distribution now scans and adds to the call graph only the files its `*.dist-info/RECORD` lists; a distribution without a RECORD owns the files no other distribution lists. Each such finding is reported once, under its owner, with the same file path, lines and `finding_id` as the owner's copy before; the copies under the other distributions are gone. Call-graph functions, containing-function lookups and synthesized entry-point findings in a namespace directory name the distribution that installed the file. On Certbot the 333 files of `google/` were scanned 1332 times in 4 scanner processes and now 333 times, and its 140 findings, 35 per distribution, are now 35 (31 under `google-auth`, 4 under `protobuf`). Distributions with a directory of their own are unchanged. Distributions that share a directory and have no RECORD, such as Debian-packaged `lazr.uri` and `lazr.restfulclient`, still each report the files no RECORD claims. The structural graph of such a scan changes; `graphfrag.GraphAlgoVersion` `graph-algo-6` of this release covers it. Findings cache entries for namespace distributions are keyed by the files scanned, so entries written by earlier versions are not reused.
