- `--scan-dependencies` no longer loses findings silently when OpenGrep stops a rule at its time limit. Dependency scans now pass `--timeout 30` instead of OpenGrep's default 5 s per rule and file. Before, a loaded host made the default fire on large bundled files and their findings were dropped without a warning: on one 50-package npm project, 4 of 6 loaded runs returned 64 of its 74 dependency findings. With the new limit, 6 of 6 returned all 74, and the scan took about 3% longer under that load. A dependency whose scan still stops at a time or memory limit keeps its partial findings, is logged as a warning that names the dependency and the files, and is no longer written to the dependency findings cache, so the next scan retries it. The primary project scan keeps OpenGrep's default timeout and logs the same warning for its own files.
- With `--progress`, the completed `dependencies` phase now carries `deps_incomplete`, the number of scanned dependencies whose scan stopped at a time or memory limit, and the completed `detection` phase carries `files_incomplete`, the number of files the primary scan stopped analyzing. Both are optional within scan-progress schema v1. Neither changes the exit status.
