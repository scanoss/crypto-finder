- More entry points are recognized as `root_kind` `framework_entry` or `main`, so a chain starts where a framework or the runtime enters the application, and crypto written directly in such a function is `reachable` instead of `unreachable`. The frameworks and the names they declare are a catalog kept as data, one YAML file per framework under `internal/callgraph/entrypoints/<language>/<framework>.yaml` (adding a framework is adding a file, see `docs/OUTPUT_FORMATS.md`); a name counts only when the file brings it into scope from that framework, never by its bare name. Java: `@PostConstruct`, `@PreDestroy` and `@Bean` methods; servlet, filter and listener callbacks written without `@Override` (`doGet`, `doPost` and the other `do*` methods, `service`, `init`, `destroy`, `doFilter`, `contextInitialized`) on a type that extends a servlet type; Spring `@MessageMapping`, `@ExceptionHandler`, `@StreamListener` and `@TransactionalEventListener`; Kafka and RabbitMQ class-level handlers; WebSocket `@OnMessage`, `@OnOpen`, `@OnClose` and `@OnError`; Micronaut and Quarkus routes and message consumers; and EJB `@Schedule` and `@Timeout`. A Java entry annotation, the request mapping, `@Scheduled`, `@EventListener` and listener annotations above included, now counts only when the file imports it from its framework (a single-type or on-demand import) or writes it qualified, so an annotation of the same simple name from another package is not an entry point. TypeScript and JavaScript: a handler registered with an Express, Koa, Hono or Fastify router (`app.get('/x', handler)`, `router.post`, `app.use`, `app.route('/x').get`, inline or by name, also through one wrapper such as `asyncHandler(fn)`), where the router comes from that package (`app = express()`, `express.Router()`, a parameter typed `Express`), so `cache.get('/x', fn)` is not a route; NestJS `@Get`, `@Post` and the other route, message, event and schedule decorators imported from `@nestjs/*`; Next.js app router `route.ts` method handlers, the default export and data-fetching exports of a page, layout or `pages/` file, and `middleware`, when the nearest `package.json` declares `next`; the exports of the module `package.json` `main`, `module` or `exports` names. The top level of that module, of a `bin` script and of a module that checks `require.main === module` is `main`. Python: Flask, FastAPI, Starlette and Sanic routes and request hooks (`@app.route`, `@app.get`, `@router.post`) on an application or router made by that framework, Celery, Dramatiq and RQ tasks, click and typer commands, Django signal receivers and views a `urls.py` `path`, `re_path` or `url` names, class-based view methods (`get`, `post`, the viewset actions) of a class whose base is a Django, Django REST framework, Flask or Flask-RESTful view, directly or through a class of the same file, and the console and GUI scripts `pyproject.toml`, `setup.cfg` or `setup.py` names (`main`), matched to a module as the manifest spells it or under the project's own root module, never under other leading segments; the top level of a module with `if __name__ == "__main__":` is `main`. A decorator counts only when it comes from its framework, so a `@registry.command()` of the application is not an entry point. Go: `init` functions and package variable initializers (`main`); handlers registered with net/http, gorilla/mux, chi, gin or echo (`HandleFunc`, `Handle`, `Get`, `GET`, `Method`, `Use` and the other method registrations) on a value from that package, by name, as a method value or through a conversion such as `http.HandlerFunc(h)`; `ServeHTTP(http.ResponseWriter, *http.Request)` methods; the exported methods of a type that embeds a generated gRPC `Unimplemented…Server`; and the `Run`/`RunE` functions of a `cobra.Command`. A method value is matched on the type of its receiver, so a method of the same name on another type is not an entry point. A React component is called by each component that renders it as a JSX element, a handler a JSX attribute names is called by the component, and a function written inline as a call argument is called by the function that passes it, so crypto in a Promise executor or an `onClick` arrow is reached through its host. Test code is never an entry point: a method with a JUnit or TestNG annotation, or in a file under a test source location, keeps `no_callers`, so crypto in a test stays `unreachable` when `--include-tests` puts tests in the graph.
