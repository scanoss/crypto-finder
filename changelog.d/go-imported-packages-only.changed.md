- Go `--scan-dependencies` now scans only the imported packages of each dependency module, not the whole module. A Go program contains only the packages it imports, so detection and the dependency call graph read the files directly in the directory of each package in the production import closure, and not a module's other packages, including the subdirectories of an imported package. Findings in imported packages are unchanged; findings in packages nothing imports are no longer reported. On step-ca (155 Go modules) the dependency phase drops from about 190 s to 28 s, the whole scan from about 240 s to 40 s and peak memory from about 10 GB to 0.7 GB, with 1183 dependency findings instead of 1895. Build constraints are evaluated for the scanning host, as for the module inventory, so a package imported only on another operating system or architecture is not scanned. Findings cache entries for Go dependencies are keyed by the files scanned, so entries written by earlier versions are not reused. With fewer dependency files in the call graph, a finding whose file shares its name and directory suffix with a file of a non-imported package now resolves its containing function more often, so some findings gain or change an `occurrence_key` (28 of 1435 assets on step-ca). Other ecosystems are unchanged.
- `graphfrag.GraphAlgoVersion` is now `graph-algo-6` (was `graph-algo-5`). The structural graph of a Go scan with dependencies no longer holds functions, edges or dispatch targets from packages the program does not contain, and this version also covers the Go, Node and Python call-resolution and Go interface-dispatch changes listed under Fixed. Fragments produced by earlier versions are not interchangeable with new ones, so a consumer that caches structural graphs under `scan_metadata.graph_algo_version` must re-mine. The wire schema is unchanged.
