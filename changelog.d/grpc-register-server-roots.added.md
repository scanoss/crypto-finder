- Go: the methods of a gRPC service implementation are entry points (`root_kind` `framework_entry`) when the value is passed to a generated `Register<Service>Server` or grpc-gateway `Register<Service>HandlerServer` call, so crypto in an RPC method is `reachable` instead of `no_callers` even when the type does not embed `Unimplemented<Service>Server`. The value is resolved from a `&T{}` literal, `new(T)`, a constructor (`NewT()`, `pkg.NewT()`) by the types it returns or declares, a local variable, or a parameter or field typed `*T`; a value typed as the generated interface itself (a parameter `srv pb.KeysServer`) is the types that functions declaring that interface as their result build. Only the methods of the service count: the ones the generated interface declares when it is in the scanned tree, otherwise the exported methods with a gRPC signature (`(ctx context.Context, req *Req) (*Resp, error)`, or a stream parameter and `error`). Other methods of the type, other types and a value whose type cannot be resolved stay unrooted. The catalog gains the `server_registration` shape, whose `names` are patterns.
