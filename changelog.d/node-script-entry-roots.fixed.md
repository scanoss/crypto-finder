- JavaScript and TypeScript files that run as scripts are now program entry points, so crypto at their top level (`<module>`), or reached only from it, is reachable with root kind `main`. A script is a file whose first line is a shebang naming `node`, `bun`, `deno`, `tsx` or `ts-node` (also through `env -S`), or a file a `package.json` script runs with one of those runtimes (`tsx scripts/seed.ts`, including commands chained with `&&`). Plain library modules, and files only a linter or test runner names, stay non-entries. Also fixed: two files of one directory with the same name and different extensions (`run.ts` and `run.mjs`) shared one module identity, so one of them lost its top-level declaration and its findings came out `not_applicable` with `no_containing_function`; the file Node resolves for `./run` keeps the identity and the other keeps its extension (`run.mjs`).
