- Go and C contracts that carry no `parameter_types` now resolve a literal key-size argument positionally, on terminal and supporting calls alike. Every Go, C and C++ `keySize` contract parameter was audited against the library's headers and docs, and byte counts no longer read as bits. `derivation: argument_byte_length` now applies to HACL* HMAC `key_len`, libsodium and Monocypher BLAKE2 key lengths, LibTomCrypt (`*_setup`, `*_init`, `*_memory`, `rsa_make_key`), NSS (`PK11_KeyGen`, `PK11_TokenKeyGen`, `PK11_Derive`, `PK11_UnwrapSymKey`, `PK11_CreatePBEV2AlgorithmID`), wolfSSL (`wc_AesSetKey`, `wc_HmacSetKey`, `wc_curve25519_make_key` and the other symmetric, MAC, KDF and Curve/Ed25519 key-size arguments), and the golang-fips and Microsoft `PBKDF2` key length. For example `wc_AesSetKey(aes, key, 16, ...)` reports 128 bits, not 16. The `keySize` contribution was removed where the unit was unclear (wolfSSL `wc_ecc_make_key*`, `wc_ecc_set_curve`, `wc_ed448_make_key` and LibTomCrypt `ecc_make_key`), so those report no key length instead of a wrong one. Bit-count arguments such as `RSA_generate_key_ex`, `EVP_PKEY_CTX_set_rsa_keygen_bits`, `rsa.GenerateKey` and `wc_MakeRsaKey` and the sigstore RSA signer-verifier constructors are unchanged. (#716)
