- In Go, a call on a loop variable now has an edge when the ranged collection's element type is known: `for _, s := range m.sources { s.Load() }` over a slice, array or map struct field (and `xs[i].M()` on one), or over a typed local, parameter or composite literal. A concrete element type links exactly to the method, and an interface element type fans out to its implementers. Before, the loop variable had no type and the call got no edge, so code reached only through such a loop read unreachable. A channel, string, integer or function range, an `any` or `interface{}` element, a named slice type, a call result and a name redeclared inside the loop stay unresolved. The parameters of a function literal now shadow outer names inside it.
