- A finding whose rule has a `parameterCondition` that every route contradicts now reads `unreachable` (`reachable: false`) instead of `reachable` with no chain. Each route's caller passes an argument that refutes the condition, for example `MessageDigest.getInstance(alg)` reached only with `"SHA-1"` and `"SHA-256"` under a rule for `param[0]==MD5`, so the crypto the rule describes runs on no known route. This is the answer the graph fragment's `crypto_entry_points` already gave by not listing the finding. When the chain budget left a route or a call site into the function unexamined, the finding reads `unknown` with `unresolved_reason: "traversal_truncated"`, because an unexamined call may satisfy the condition. A route whose argument did not resolve still keeps the finding `reachable`.
