- Go `--scan-dependencies` now skips the dependency files that the host build excludes. Within each imported package, detection and the dependency call graph read only the Go files the build compiles for the machine running the scan (its `GOOS`, `GOARCH`, build tags and `CGO_ENABLED`): a file for another platform such as `*_windows.go` or `*_darwin.go` on Linux, a file whose build tag is not set, and a `//go:build ignore` generator are no longer scanned, and findings in them are no longer reported. Non-Go files in a package directory, which no Go rule matched, are no longer passed to detection either. On step-ca the dependency findings drop from 1183 to 1176, all 7 in excluded files (`root_darwin.go`, `rootcerts_darwin.go`, `tpm_windows.go`, and the `//go:build ignore` files `root_darwin_arm_gen.go` and `x509_test_import.go`); findings in compiled files are unchanged. A project importing `modernc.org/libc`, which ships one 4 MB generated file per platform, parses one of them instead of eight: on a small module importing it, the dependency call graph drops from about 54 s to 6.5 s, the scan from about 69 s to 18 s and peak memory from about 3.4 GB to 1 GB. Findings cache entries for Go dependencies are keyed by the files scanned, so entries written by earlier versions are not reused. The structural graph of a Go scan with dependencies no longer holds functions from excluded files; `graphfrag.GraphAlgoVersion` `graph-algo-6` of this release covers this change.
