- `--scan-dependencies` now shares the CPU cores between concurrent dependency scans. When two or more dependency scans run at once, each OpenGrep run gets `--jobs` set to the CPU cores divided by the number of concurrent scans, which `--dep-workers` bounds. Before, every run used OpenGrep's default of one job per detected core, so the default 8 concurrent runs asked for 8 jobs per core. Under that contention OpenGrep's per-file timeouts dropped findings in large bundled files: 8 concurrent scans of one npm package each returned 14 of its 28 findings, and now return all 28. On a 50-package npm project the dependency phase went from 150 s to 120 s. A single dependency scan and the primary project scan keep OpenGrep's default. The job count is not part of the dependency findings cache key.
