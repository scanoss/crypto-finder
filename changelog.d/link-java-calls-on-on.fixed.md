- A Java call on a type imported only on demand (`import com.nimbusds.jwt.proc.*;`) now links to the type in the package that declares it. The parser keyed such a type on the calling file's own package, or on its first on-demand import, without knowing which package declares it; the call now moves to the one package, among the file's own and its on-demand imports, that declares the type in the scanned source, the file's own package first. A name two on-demand imports both declare is left as it was. A call on a type that declares no method of that name now links to the method the type inherits and to the implementations in its known subtypes also when the type is an interface, or declares no method at all. Together these left the HS256 ID token check of `oauth2-oidc-sdk`'s `IDTokenValidator.validate` with no edge into `nimbus-jose-jwt`: `ConfigurableJWTProcessor.process` and `SignedJWT.verify` named types in the wrong package, and `ConfigurableJWTProcessor`, an empty interface, took `process` from `JWTProcessor`. The route to `MACVerifier.verify` now holds with `exact` and `interface_dispatch` edges.
