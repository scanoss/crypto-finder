- A Python project nested below the scan root (a monorepo's `packages/<name>/src/<import_name>/` with a `pyproject.toml`, `setup.py` or `setup.cfg` beside it) is now keyed by its import name, so `from <import_name>.module import X` links to the declaration. Before, the modules kept the `packages.<name>.src.` prefix, no import matched, and crypto reached only through such an import read as having no callers. The directories above the project name nothing, and its `src` or `lib` directory is transparent. A project that defines a top-level module another project already defined, or whose directory is itself a package, keeps its directory prefix: no two projects share a key and no import is matched by suffix. Names every project has its own copy of (`tests`, `docs`, `examples`, ...) do not count as a collision.
