- Python `--scan-dependencies` now scans every top-level package and module a distribution installed, the same ones on every run. A distribution with several, such as `configobj` (`configobj` and `validate`), `PyYAML` (`yaml` and `_yaml`) or setuptools (`setuptools`, `pkg_resources` and `_distutils_hack`), was scanned and added to the call graph for only one of them, picked at random per run, so findings and call-graph functions changed between runs of the same version on the same environment. A distribution whose randomly picked name was a module file, and every distribution that is a single module file, such as `six` or `typing_extensions`, was skipped. These distributions now have `site-packages` as their root and list the files of each of their packages and module files, so their finding paths start with the package name (`validate/__init__.py`, `six.py`) where they were relative to the one package picked, and their `finding_id` values change accordingly. A distribution with exactly one package directory is unchanged: same root, paths, `finding_id` values and findings cache keys. On Certbot, 7 distributions (`configobj`, `PyYAML`, `google-api-python-client`, `six`, `typing_extensions`, `ConfigArgParse`, `google-auth-httplib2`) gain the roots they were missing, and on a larger environment 20 do, including setuptools, `attrs`, `pytest` and `python-apt`, for about 2% more files scanned. With the Semgrep scanner, a dependency limited to some files of its directory (a Go module's imported packages, a Python namespace distribution's own files, or a distribution rooted at `site-packages`) now keeps only the findings in those files, instead of every finding in the directory. The structural graph of a Python scan with such distributions changes; `graphfrag.GraphAlgoVersion` `graph-algo-6` of this release covers it.
