- Findings whose rule-matched call is itself the key-size call now carry `resolved_key_length`. Python `rsa.generate_private_key(key_size=2048)` or `key_size=KEY_SIZE`, Go `rsa.GenerateKey(rand.Reader, 2048)`, C `RSA_generate_key_ex` and `EVP_PKEY_CTX_set_rsa_keygen_bits`, and Java `KeyPairGenerator.initialize(2048)`, `initialize(BITS)` and `new RSAKeyGenParameterSpec(3072, F4)` previously reported no size, because only supporting calls were evaluated. The matched call is now emitted as a supporting-call entry, so consumers that join `finding_graphs[].supporting_call_ids` to `supporting_calls[].supporting_call.resolved_key_length` read the size with no change. A rule-declared `keyLength` that disagrees keeps both values (`rule_declared_bits`, `rule_conflict`). The schema is unchanged. Go and C contracts without `parameter_types` now resolve a literal key-size argument positionally on supporting calls too. (#716)
